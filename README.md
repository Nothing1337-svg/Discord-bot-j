# Discord-bot-j — automatic video alerts

Бот автоматически отправляет ссылки на новые видео выбранных авторов в каналы Discord.
Встроенные источники: **YouTube, Twitch, TikTok, Instagram/Reels, Vimeo, PeerTube**, плюс RSS/Atom.
Российские платформы не входят в набор интеграций. Русский язык интерфейса сохранён, доступен также английский.

Это не поиск всех видео интернета: администратор задаёт авторов/подключения и каналы назначения.
TikTok и Instagram требуют авторизации аккаунта, поэтому произвольного автора по нику подключить нельзя.
Реальные ограничения, настройка каждого источника и первичные источники: [docs/platforms.md](docs/platforms.md).
[Изученные альтернативы и неподдержанные платформы](docs/alternatives.md).

## Быстрый запуск (Python 3.11+, macOS/Linux)

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt -c constraints.txt
cp .env.example .env
# Заполнить реальные DISCORD_TOKEN и GUILD_ID в .env
python -m bot.doctor
python -m bot.main
```

В `.env.example` token, guild ID, API keys и OAuth tokens намеренно пустые.
Для YouTube по UC-ID и публичного PeerTube токены платформ не нужны. Для Twitch — собственные
`TWITCH_CLIENT_ID` и `TWITCH_CLIENT_SECRET`. Для YouTube @handle — `YOUTUBE_API_KEY` (только разрешение
handle при добавлении; дальнейшие проверки идут по Atom-ленте без расходов Data API quota).

Для TikTok, Instagram и Vimeo скопировать `accounts.example.json` в `accounts.json`, заполнить нужные
подключения и удалить ненужные примеры. Поля `token_env` — **названия** переменных, сами токены только в `.env`
или окружении процесса. `accounts.json` и `.env` исключены из Git и Docker image. Подключений каждого типа
может быть несколько. [Пошаговая настройка](docs/platforms.md#авторизованные-подключения).

Нужен постоянно работающий хост с исходящим HTTPS/WSS к Discord и платформам. Входящие порты не требуются.
**Один экземпляр бота на одну базу данных.** На macOS/Linux процесс держит `data/bot.lock`; второй экземпляр с тем же каталогом откажется запускаться. Блокировка снимается при выходе процесса, удалять lock-файл вручную не нужно.
При смене токена перезапустить процесс. Веб-интерфейс OAuth и автоматическое продление пользовательских
токенов TikTok/Instagram не реализованы: сроки и продление контролирует администратор. Twitch app token
бот получает и перевыпускает автоматически.

## Discord

Установить приложение на сервер со scopes **bot** и **applications.commands**.
Команды синхронизируются только для реального `GUILD_ID`; бот обслуживает один сервер.

- Intents: **Guilds**, **Guild Voice States**. Привилегированные Members, Presence и Message Content не нужны.
- Права в каналах рассылки: **View Channel**, **Send Messages**, **Embed Links**.
- Для файлов `/subscriptions`, `/banner_preview`: **Attach Files** в канале команды.
- Для изменения серверного баннера: **Manage Server** и feature **BANNER** у сервера.
- Пользователю для управления командами нужен **Manage Server**, проверяется при каждом вызове.
- Administrator, Manage Roles, Connect, Speak и Read Message History боту не требуются.

## Команды

| Команда | Действие |
|---|---|
| `/platforms` | Источники и подсказка о настройке |
| `/subscribe platform:… source:… channel:…` | Проверить источник, запомнить старые записи, включить авторассылку новых |
| `/subscriptions` | Файл UTF-8 со всеми подписками, ID и каналами |
| `/unsubscribe subscription_id:…` | Удалить подписку, очередь и её историю |
| `/check` | Запросить внеочередную проверку; cooldown команды 30 секунд на сервер |
| `/status` | Работает ли цикл, число ошибок, очередь, число источников с ограниченным окном API |
| `/banner_preview` | PNG текущего голосового онлайна без изменения сервера |

Примеры формата (заменить авторов и каналы реальными):

```text
/subscribe platform:youtube source:<UC-ID или https://youtube.com/@handle> channel:<канал>
/subscribe platform:twitch source:<логин> channel:<канал>
/subscribe platform:tiktok source:my_tiktok channel:<канал>
/subscribe platform:instagram source:my_instagram channel:<канал>
/subscribe platform:vimeo source:my_vimeo channel:<канал>
/subscribe platform:peertube source:<https://instance/video-channels/channel> channel:<канал>
/subscribe platform:rss source:<конечный HTTPS URL ленты> channel:<канал>
```

Авторассылка начинается после `/subscribe`; повторять `/check` не нужно. Бот не читает сообщения пользователей
и не пересылает найденные в них ссылки. Старт live-эфиров, Twitch Clips, Instagram Stories и карусели
не отслеживаются. YouTube Shorts приходят вместе с обычными видео, без отдельного фильтра.

## Как работает доставка

По умолчанию проверка каждые `POLL_SECONDS=120` (минимум 30) плюс время последовательного обхода.
Не более `MAX_SEND_PER_POLL=5` отправок на подписку за один проход. RSS ограничен объёмом выдачи источника.
API ограничены `API_MAX_PAGES=3` (1–10); достижение границы видно в `/status`. Это предел просмотренной истории,
а не гарантия потери: всё обнаруженное сохраняется, но содержимое за пределом окна бот не видит.

SQLite `data/bot.sqlite3` сохраняет подписки, ID доставленных видео и очередь. При создании подписки текущая
выдача становится baseline **без отправки старых видео**. Для новых подписок видео с датой публикации раньше секунды начала подписки исключаются, даже если раньше не попадали в выдачу. Граница округляется вниз до секунды: API часто не возвращают доли секунды, и иначе новый ролик на этой границе мог потеряться. Для RSS без даты применяется только
baseline/ID, поэтому такое исключение гарантировать нельзя. Пустая действительная лента допустима;
непустая лента без пригодных HTTPS-ссылок отклоняется.

Получение и доставка имеют отдельный backoff. Сбой Discord не останавливает сбор новых видео; недоступный
источник не мешает доставлять уже сохранённую очередь после завершения его попытки запроса. Retry-After
в секундах или формате HTTP-date и Twitch Ratelimit-Reset учитываются (задержка по заголовкам ограничена 24 часами), обычный backoff растёт от 240 секунд до часа. Автоматическая
проверка и `/check` сериализованы. Ошибка SQLite при чтении списка подписок не уничтожает цикл: выполняется повтор на следующем проходе, а `/status` показывает ошибку. Упоминания @everyone/ролей/пользователей отключены.

ID отмечается доставленным после ответа Discord. **Exactly-once не обещается**: авария между приёмом сообщения
Discord и записью SQLite может вызвать повтор. Видео, исчезнувшие из выдачи между проверками или вышедшие
за лимит страниц во время долгого простоя, восстановить нельзя. RSS передаёт все записи: выберите именно
видеоленту, иначе придут также статьи. Ссылки HTTPS до 2000 символов; приватные сетевые адреса и redirects
запросов отключены. Используйте конечный URL. Vimeo передаёт только доступные публичные видео.

При обновлении со старой версии SQLite мигрируется без удаления подписок/очереди. У старых подписок дата
начала неизвестна: для них сохраняется прежняя дедупликация по ID. Пересоздание подписки включает защиту
по дате, но намеренно делает текущую выдачу новым baseline. Перед обновлением остановить бот и сделать
резервную копию каталога `data`; не удалять его для установки новой версии.

## Дополнительный баннер голосового онлайна

`BANNER_ENABLED=false` по умолчанию. Включать только если нужен баннер и есть Manage Server + BANNER.
Без них авторассылка продолжает работать. Считаются уникальные люди в Voice и Stage, включая слушателей,
с выключенным микрофоном/звуком; боты исключены. AFK исключён при `EXCLUDE_AFK=true`. Это количество сейчас,
не накопленные часы. Для закрытых каналов дать View Channel. Временная недоступность сервера пропускается.

Debounce — 5 секунд после изменения количества; cooldown — минимум 60 секунд между попытками загрузки,
включая неуспешные (настройка не ниже 30). Неизменное значение повторно не загружается. Изменение во время
загрузки учитывается следующим обновлением. При отсутствии прав/capability обновление отключается до перезапуска.

Фон: заменить `assets/background.png` или задать `BACKGROUND`. Размер результата **960×540**, центральная
обрезка и тёмная панель. Перезапустить бот после замены. Разметка — `bot/banner.py`.
Язык: `LANGUAGE=ru` или `en`, перезапуск; переводы в `bot/i18n.py`. Slash-имена английские, описания двуязычные.
Технические ошибки могут быть английскими, названия видео сохраняют язык автора.
Unicode обрабатывается по графемам (`regex`), кириллица/латиница — Noto Sans, emoji — монохромный Noto Emoji.
Неизвестные символы заменяются `?`; длинный текст обрезается. Цветные/custom Discord emoji и полное покрытие
сложных ZWJ/CJK не обещаются. Шрифты поставляются с OFL-лицензией.

Остановка через Ctrl+C/SIGTERM сначала отменяет выполняющиеся команды и фоновые задачи, затем закрывает HTTP и SQLite. Это также действует при штатной остановке контейнера; SIGKILL штатное завершение выполнить не позволяет.

## Docker

Создать `.env` с реальными данными и **`accounts.json`** (для источников без аккаунтов достаточно `{}`).

```sh
docker compose up -d --build
```

SQLite хранится в named volume; accounts.json монтируется read-only. Никогда не выполнять `down -v`,
если требуется сохранить историю. Изменённый фон/код требует пересборки. Docker-конфигурация подготовлена;
локальный Docker CLI отсутствует, запуск контейнера не подтверждён.

## Проверки и зависимости

```sh
pip install -r requirements-dev.txt -c constraints.txt
pytest -q
ruff check .
python -m bot.doctor
python -m bot.preview
```

`doctor` — локальная проверка настроек, не вход в Discord; при недостающих данных возвращает код 1.
[Результаты тестирования](docs/testing.md), [структура проекта](docs/structure.txt).
Демонстрационные PNG: `previews/banner-ru.png`, `banner-en.png`, `banner-unicode.png`; числа в них тестовые.

Зависимости: discord.py, aiohttp, certifi (проверенные TLS-соединения), feedparser, Pillow, python-dotenv, fonttools, regex. SQLite встроен в Python.
Проверки: pytest, pytest-asyncio, Ruff. Проверенные версии и транзитивные зависимости — `constraints.txt`.
Реальный запуск требует token/GUILD_ID, установки приложения, прав, авторов и каналов назначения, а для
авторизованных платформ — действующих credentials. Эти значения нигде не выдумываются.

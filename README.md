# Discord-bot-j

Самостоятельно размещаемый Discord-бот: новые видео YouTube, Twitch и RSS/Atom автоматически отправляются в выбранные текстовые каналы. Дополнительно — серверный баннер с текущим голосовым онлайном. Python 3.11+.

**«Все платформы» без ограничений не поддерживаются.** Для платформ без встроенного адаптера нужен действующий публичный RSS/Atom-мост. Матрица поддержки, ограничения и сравнение аналогов: [docs/alternatives.md](docs/alternatives.md).

## Запуск

В каталоге проекта:

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt -c constraints.txt
cp .env.example .env
# Заполните .env реальными данными
python -m bot.main
```

В `.env` обязательно указать **DISCORD_TOKEN** и **GUILD_ID**. Поля намеренно пустые. Токен храните локально, не публикуйте в Discord/GitHub. Для Twitch дополнительно нужны `TWITCH_CLIENT_ID` и `TWITCH_CLIENT_SECRET`, полученные в [Twitch Developer Console](https://dev.twitch.tv/console).

Для круглосуточной работы нужен постоянно работающий компьютер/VPS и исходящий HTTPS/WSS к Discord и источникам. Один процесс на одну SQLite. Входящие порты не нужны.

Альтернативно: `docker compose up -d --build`. Заполните `.env` до запуска. Именованный volume сохраняет базу при пересоздании контейнера. При изменении фона/кода пересоберите образ. Docker-конфигурация подготовлена; её запуск отдельно не проверялся.

## Discord: установка, Intents и Permissions

1. Создать приложение и Bot в [Discord Developer Portal](https://discord.com/developers/applications).
2. Установить на свой сервер со scopes **bot** и **applications.commands**.
3. Intents: **Guilds**, **Guild Voice States** (включены в коде). Privileged **Server Members**, **Presence**, **Message Content** не нужны.
4. В каналах рассылки дать **View Channel**, **Send Messages**, **Embed Links**. Для файлов `/subscriptions` и `/banner_preview` — **Attach Files** в канале команды. Необходимые каналы должны быть доступны боту.
5. Для изменения серверного баннера дать **Manage Server / Manage Guild** и убедиться, что сервер имеет feature **BANNER**. Бот проверяет capability сервера, а не предполагает уровень бустов. При отсутствии возможности рассылка продолжает работать, баннер отключается до перезапуска.
6. Для управления командами пользователю нужен **Manage Server**; есть проверка во время выполнения. Administrator, Manage Roles, Connect, Speak и Read Message History боту не нужны. Для подсчёта закрытых голосовых каналов обеспечьте боту View Channel.

Команды синхронизируются только с `GUILD_ID`. Приложение обслуживает один сервер.

## Команды и автоматическая отправка

- `/subscribe platform:youtube source:<реальный UC-ID> channel:<канал>`
- `/subscribe platform:twitch source:<логин автора> channel:<канал>`
- `/subscribe platform:rss source:<конечный HTTPS URL ленты> channel:<канал>`
- `/subscriptions` — UTF-8 файл со всеми подписками и ID.
- `/unsubscribe subscription_id:<ID>` — удалить подписку и её состояние.
- `/check` — запустить проверку сейчас; cooldown команды 30 секунд на сервер, backoff неисправных источников сохраняется.
- `/status` — число подписок, источников с ошибкой, голосовой онлайн и состояние баннера.
- `/banner_preview` — PNG без изменения сервера.

При добавлении подписки текущие записи заносятся в baseline **без отправки старых роликов**. Проверка идёт каждые `POLL_SECONDS=120` (минимум 30), плюс длительность обхода источников. Ролики отправляются автоматически, без вызова команд. По умолчанию максимум `MAX_SEND_PER_POLL=5` сообщений на подписку за проход.

SQLite `data/bot.sqlite3` хранит подписки, доставленные ID и очередь обнаруженных видео. Очередь переживает перезапуск и исчезновение ролика из выдачи. ID помечается доставленным только после успешного ответа Discord. Параллельные проверки сериализованы. Ошибка одного источника не блокирует остальные; интервалы повтора растут от 240 секунд до 1 часа. Discord rate limits обрабатывает discord.py. @everyone и все mention-пинги отключены.

Гарантия exactly-once невозможна: если процесс упадёт после приёма сообщения Discord, но до записи SQLite, возможна повторная отправка. Видео, опубликованные и исчезнувшие из ограниченной выдачи **между проверками**, восстановить нельзя. Изменение заголовка не вызывает новую отправку; удаление/добавление подписки создаёт новый baseline. Порядок предполагает обычную ленту «новые сверху». База seen растёт со временем; сохраняйте резервные копии и свободное место.

## Голосовой онлайн и обновление баннера

Считаются уникальные люди, находящиеся сейчас в Voice и Stage, включая слушателей Stage и пользователей с выключенным микрофоном/звуком. Боты не учитываются. AFK-канал исключается при `EXCLUDE_AFK=true`. Это количество участников, **не часы в голосе** и не Discord presence online/offline. Бот использует voice-state cache discord.py; подключаться к голосу не требуется.

Баннер выключен по умолчанию. Включение: `BANNER_ENABLED=true`. После подключения счётчик восстанавливается из состояния сервера; затем обновляется по voice events и периодической проверке кеша.

- **Debounce 5 секунд**: отсчёт от последнего изменения количества. Одинаковое количество не сбрасывает таймер.
- **Cooldown 60 секунд** (минимум 30): минимальный интервал между попытками загрузки. Ошибка тоже расходует интервал.
- Загружается последнее значение; неизменный счётчик не перерисовывается. Изменение во время загрузки будет обработано следующим обновлением.
- Нет прав или BANNER — отключение обновления с записью в журнал; после исправления нужен перезапуск.

## Фон, язык, Unicode и Emoji

Замените `assets/background.png` своим PNG/JPEG или задайте `BACKGROUND=путь/к/файлу.png`. Относительные пути считаются от корня проекта. Изображение масштабируется с центральной обрезкой до **960×540**, поверх накладывается тёмная панель. Перезапустите бота, чтобы применить фон, даже если число участников не изменилось. Панель/цвета/позиции редактируются в `bot/banner.py`.

`LANGUAGE=ru` или `LANGUAGE=en` в `.env`, затем перезапуск. Переводы — `bot/i18n.py`. Названия slash-команд стабильные английские; описания двуязычные, диагностические сообщения могут быть английскими. Заголовки видео сохраняют язык автора.

Файлы и RSS — Unicode/UTF-8. Discord отображает обычные Unicode emoji своим клиентом. Для PNG встроены Noto Sans и монохромный Noto Emoji с OFL-лицензией. Текст разбивается по графемным кластерам (`regex \X`), шрифт выбирается по покрытию символов. Неподдерживаемый кластер заменяется `?`, длинная строка обрезается по ширине. Кириллица, латиница и простые emoji поддерживаются. Полнота CJK и сложных ZWJ-комбинаций не гарантируется, цветные emoji и Discord custom emoji `<:name:id>` в PNG не реализованы. Новые шрифты добавляются в список `fonts()`.

## Проверка без токена

```sh
pip install -r requirements-dev.txt -c constraints.txt
pytest -q
ruff check .
python -m bot.preview
```

Тестовые числа 12/128 используются только в локальных демонстрационных PNG. Для запуска бота никакие подставные token/guild ID не используются. В unit-тестах Discord/API заменены тестовыми объектами.

Примеры: `previews/banner-ru.png`, `previews/banner-en.png`, `previews/banner-unicode.png`. Результаты проверки — [docs/testing.md](docs/testing.md). Полный список файлов — [docs/structure.txt](docs/structure.txt).

## Зависимости

`discord.py` — Discord API и slash-команды; `aiohttp` — HTTP; `feedparser` — RSS/Atom; `Pillow` — PNG; `python-dotenv` — `.env`; `fonttools` — покрытие шрифтов; `regex` — графемы. SQLite — стандартная библиотека Python. Тесты: `pytest`, `pytest-asyncio`, `ruff`. Проверенные версии и транзитивные зависимости закреплены в `constraints.txt`.

## Что требуется для реального запуска

Реальные `DISCORD_TOKEN`, `GUILD_ID`, установка бота на сервер, права в каналах, авторы/ленты и каналы назначения. Twitch требует собственные OAuth credentials. Серверный баннер требует feature BANNER и Manage Server; рассылка от баннера не зависит. Нужен постоянно работающий хост. Реальная отправка в Discord и обновление баннера не проверены без этих данных.
